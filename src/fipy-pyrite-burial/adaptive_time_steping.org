- The only “error” you can measure cheaply is the *max‑norm change* of all state variables between two successive sweeps (=max_change=).  
- The physics is advection‑diffusion‑reaction, so a CFL‑type restriction is useful but you do not want to recompute it every cell – a global estimate is enough.  

Below are three very low‑overhead ways to make the choice of =current_dt= more robust:

| Strategy | What it adds | Why it helps |
|---|---|---|
|1️⃣ *Safety‑factor based growth*|Limit the growth factor to a user‑defined “safety” (e.g. 0.8) and only increase the step when the change is /significantly/ smaller than the tolerance.|Avoids the “burst‑growth” problem where a single lucky step suddenly pushes =dt= to the max and the next step fails.|
|2️⃣ *CFL‐type upper bound*|Compute a global diffusion/advection limit =dt_cfl = min(dx/|v|, dx²/(2 D))= and cap =current_dt= by it.|Guarantees numerical stability for explicit‑type terms even though FiPy solves implicitly; it also keeps the physical time‑scale visible.|
|3️⃣ *PID‑controller (H211B)*|Use the classic H211B controller (=dt_new = dt * (err/err_prev)^{kP} * (err/err_ref)^{kI} * (err_prev/err_ref)^{kD}=) with modest gains (kP≈0.075, kI≈0.175, kD≈0.01).|Provides smooth, proportional step‑size adaptation that reacts to both the current error and its trend.|

# Adaptive‑time‑step helper (Python 3.13)

from __future__ import annotations

import math
from dataclasses import dataclass
from typing import Callable

Number = float | int


@dataclass
class AdaptiveDT:
    """Container for PID‑controlled adaptive time stepping.

    Parameters
    ----------
    dt_min, dt_max : Number
        Hard bounds for the step size.
    dt_initial : Number
        Starting step (usually ``mp.dt_min``).
    dt_cfl_factor : Number, default 0.8
        Safety factor applied to a CFL‑based upper bound.
    growth_factor : Number, default 1.2
        Maximum allowed growth per successful step (used if PID is disabled).
    cut_factor : Number, default 0.5
        Maximum allowed reduction per failed step.
    pid : bool, default True
        Switch to the PID controller; if ``False`` the simple
        “grow‑on‑success, cut‑on‑failure” logic is used.
    kP, kI, kD : Number
        PID gains (H211B recommended values are kP=0.075, kI=0.175,
        kD=0.01).  Ignored when ``pid=False``.
    """

    dt_min: Number
    dt_max: Number
    dt_initial: Number
    dt_cfl_factor: Number = 0.8
    growth_factor: Number = 1.2
    cut_factor: Number = 0.5
    pid: bool = True
    kP: Number = 0.075
    kI: Number = 0.175
    kD: Number = 0.01

    # internal state (do not set manually)
    _dt: Number = 0.0
    _err_prev: Number = math.inf
    _dt_prev: Number = 0.0

    def __post_init__(self) -> None:
        self._dt = max(self.dt_min, min(self.dt_initial, self.dt_max))

    @property
    def dt(self) -> Number:
        """Current time step (read‑only)."""
        return self._dt

    def _cfl_limit(
        self,
        dx: Number,
        vel: Number,
        D: Number,
    ) -> Number:
        """Simple global CFL estimate for advection‑diffusion."""
        # avoid division by zero – set a huge number if the term is irrelevant
        adv_limit = math.inf if vel == 0 else dx / abs(vel)
        dif_limit = math.inf if D == 0 else dx * dx / (2 * D)
        return self.dt_cfl_factor * min(adv_limit, dif_limit)

    def update(
        self,
        max_change: Number,
        dt_cfl: Number | None = None,
        step_success: bool = True,
    ) -> Number:
        """Compute the next ``dt``.

        Parameters
        ----------
        max_change : Number
            ‖uⁿ⁺¹‑uⁿ‖∞ from the just‑completed step.
        dt_cfl : Number | None, optional
            Global CFL bound (if you have ``dx``, ``vel`` and ``D`` handy).
        step_success : bool, default True
            ``False`` if the linear solve diverged and you had to retry.

        Returns
        -------
        Number
            New time step, already clipped to ``[dt_min, dt_max]``.
        """
        # ------------------------------------------------------------------
        # 1️⃣  Apply CFL cap (if supplied)
        # ------------------------------------------------------------------
        if dt_cfl is not None:
            self._dt = min(self._dt, dt_cfl)

        # ------------------------------------------------------------------
        # 2️⃣  Failure handling – always cut
        # ------------------------------------------------------------------
        if not step_success:
            self._dt = max(self._dt * self.cut_factor, self.dt_min)
            # keep the previous error for the next successful step
            self._err_prev = max_change
            return self._dt

        # ------------------------------------------------------------------
        # 3️⃣  Successful step – decide via PID or simple growth
        # ------------------------------------------------------------------
        if self.pid:
            # reference error – you can tie it to the user tolerance
            err_ref = max(self.dt_min, self.dt_max) * 1e-6  # tiny number ≈ machine eps
            # avoid division by zero on the very first step
            err = max(max_change, 1e-30)
            err_prev = max(self._err_prev, 1e-30)

            # H211B controller
            factor = (
                (err / err_prev) ** self.kP
                * (err / err_ref) ** self.kI
                * (err_prev / err_ref) ** self.kD
            )
            # limit the factor to the user‑provided growth/cut bounds
            factor = max(self.cut_factor, min(self.growth_factor, factor))
            self._dt = max(self.dt_min, min(self._dt * factor, self.dt_max))
        else:
            # Very simple logic: grow if the change is *much* smaller than the tolerance
            if max_change < 0.5 * self.dt_tolerance:  # type: ignore[attr-defined]
                self._dt = min(self._dt * self.growth_factor, self.dt_max)
            else:
                self._dt = max(self._dt * self.cut_factor, self.dt_min)

        # ------------------------------------------------------------------
        # 4️⃣  Store state for the next iteration
        # ------------------------------------------------------------------
        self._err_prev = max_change
        self._dt_prev = self._dt
        return self._dt

*** Why this is an /improvement/

| Benefit | Explanation |
|---|---|
|*Smooth growth*|PID (or the capped growth factor) prevents the step from jumping from =1e‑5 s= to =dt_max= in a single iteration, which is a common cause of the “solver diverges on the next step”.|
|*Physical stability*|The global CFL cap guarantees you never exceed the advection/diffusion stability limit, even though the matrix solve is implicit. It also makes the chosen =dt= easier to interpret.|
|*Graceful failure recovery*|When the linear solver throws, the helper automatically halves the step and *does not* corrupt the stored error history.|
|*One‑line integration*|All the logic lives in =AdaptiveDT.update=; you only replace ~5 lines in your loop. No additional libraries, no heavy bookkeeping.|
|*Tunable but sane defaults*|The H211B gains (0.075/0.175/0.01) work well for a broad class of stiff reaction‑transport problems; you can keep them or switch =pid=False= for the ultra‑simple “grow‑on‑success, cut‑on‑failure” scheme.|

Feel free to adjust the safety factor (=dt_cfl_factor=), the PID gains, or drop the PID altogether – the helper is deliberately minimal so you can experiment without touching the rest of the solver.

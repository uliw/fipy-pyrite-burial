Below is a *minimal, drop‑in change* that turns the =LinearLUSolver= you are currently using into a PETSc‑based Krylov solver.  
All the rest of the code can stay exactly the same – FiPy will hand the assembled matrix over to PETSc, and you get access to the full suite of KSP/PC options.

---

** 1.  What you need beforehand  

| Requirement | How to satisfy |
|------------|----------------|
| *FiPy compiled with PETSc* | Install =petsc4py= *before* (or after) installing FiPy, e.g. =conda install -c conda-forge petsc4py fipy= or =pip install petsc4py fipy=. FiPy will automatically detect PETSc at import time. |
| *PETSc libraries* | Usually come with the =petsc4py= wheels. If you built PETSc yourself, make sure the =PETSC_DIR=/=PETSC_ARCH= environment variables point to the correct install. |
| *Optional: a good preconditioner* | For 2‑D/3‑D advection‑diffusion‑reaction problems the =hypre= BoomerAMG or an =ilu= (incomplete LU) are the most robust choices. =hypre= is shipped with PETSc. |

---

** 2.  Replace the LU solver with a PETSc solver  

#+begin_src python
# ------------------------------------------------------------------
# 1️⃣  IMPORT PETSc‐enabled solver (instead of LinearLUSolver)
# ------------------------------------------------------------------
from fipy.solvers import PETScSolver   # <-- new import

# ------------------------------------------------------------------
# 2️⃣  Choose a KSP/PC pair that matches the physics
# ------------------------------------------------------------------
#   • The transport part (convection + diffusion) makes the matrix
#     *non‑symmetric* → use GMRES or BiCGStab.
#   • The reaction terms can be stiff → a robust preconditioner is
#     essential.  For moderate‑size problems an ILU works, for large
#     3‑D problems “hypre” (BoomerAMG) is usually the best.
#
#   The dictionary below is passed to PETScSolver; any PETSc option
#   can be added (see PETSc docs for the full list).

petsc_opts = {
    # Krylov method
    "ksp_type": "gmres",          # alternatives: bicgstab, tfqmr, cg (only for SPD)
    # Preconditioner
    "pc_type": "hypre",           # alternatives: ilu, bjacobi, gamg, sor, none
    # Tolerances
    "ksp_rtol": mp.tolerance,     # relative tolerance (same as you used for LU)
    "ksp_atol": 0.0,
    # Maximum Krylov iterations (optional)
    "ksp_max_it": 1000,
    # Restart for GMRES (optional, helps memory)
    "ksp_gmres_restart": 100,
    # Verbosity (set to 0 for silent)
    "ksp_monitor": None,          # set to True to see residual history
}
# Create the solver once (outside the time loop – the same object is reused)
solver = PETScSolver(**petsc_opts)
#+end_src

> *Why GMRES + hypre?*  
> /GMRES/ handles the non‑symmetric convection term without any extra work.  
> /hypre/ (BoomerAMG) is a multigrid preconditioner that scales almost linearly with the number of cells and works well for diffusion‑dominated blocks; it also copes with the reaction Jacobian if the diagonal entries are large.

If you run on a modest mesh (a few‑thousand cells) you can also try a direct LU via PETSc:

#+begin_src python

#+end_src

but for the “real” 2‑D/3‑D problems the Krylov + multigrid combo is far more memory‑efficient.

Below is a short “road‑map” for making a *1‑D, < 1 000 cell, super‑stiff* FiPy model run faster.  
I keep the recommendations grouped by /what you can change inside FiPy/ and /what you can do outside FiPy/ (i.e. call a different time‑integrator).

---

** 1️⃣  Inside FiPy – make the linear solve as cheap as possible  

| Item | Why it helps | One‑liner change (or comment) |
|------|--------------|------------------------------|
| *Direct LU (SuperLU / MUMPS) instead of an iterative Krylov* | For < 1 000 unknowns the dense factorisation is /cheaper/ than a GMRES loop that needs dozens of iterations. | =python from fipy.solvers import PETScSolver; solver = PETScSolver(ksp_type='preonly', pc_type='lu') = |
| *Scale the matrix* | Stiff reaction terms produce huge diagonal entries → condition number blows up. FiPy does an automatic scaling when you set =solver = PETScSolver(use_preconditioning=False)=; otherwise you can manually scale the coefficients (=coeff = coeff / scale_factor=). | Add a small factor, e.g. =scale = 1e-6; lhs_vars[s].setValue(lhs_vars[s].value/scale);= and later undo the scaling when interpreting results. |
| *Tighten the linear tolerance only when you need it* | The default =ksp_rtol = 1e-8= is often over‑kill for a transport‑reaction problem where the /non‑linear/ tolerance dominates. | =python solver = PETScSolver(ksp_type='gmres', pc_type='hypre', ksp_rtol=1e-5) = |
| *Reuse the matrix* | FiPy already does =useMatrixAsPreconditioner=True= by default, which means the matrix is /assembled once/ and only the RHS is updated when coefficients change. No extra code needed – just keep the same =solver= object for the whole run. |
| *Nondimensionalise* | Bringing all concentrations, diffusivities and times to O(1) reduces the spread of Jacobian entries and speeds up the Krylov convergence. | Multiply every coefficient by a characteristic scale (e.g. =C0 = 1e‑3 mol m⁻³=, =t0 = 1 yr=). Keep the scaling factors in a small dictionary so you can convert back for output. |

---

** 2️⃣  Higher‑order /BDF/ or /Rosenbrock/ time stepping  

FiPy’s =TransientTerm= is solved *implicitly with a backward‑Euler step* (first‑order BDF1).  
For a super‑stiff system you can get a /big/ speed‑up by moving to a *second‑order BDF (BDF2)* or a *Rosenbrock‑W method*.  
FiPy does *not* have a built‑in BDF2, but you can hand the ODE system over to PETSc’s *TS* (time‑stepper) or to SciPy’s =solve_ivp=.  

*** 2.1  PETSc TS (BDF2) – minimal wrapper around FiPy  

#+begin_src python
# --------------------------------------------------------------
# 1️⃣  Assemble the residual R(c) = 0   (the same as you already have)
# --------------------------------------------------------------
from fipy import CellVariable, TransientTerm, DiffusionTerm, PowerLawConvectionTerm, ImplicitSourceTerm
import numpy as np
from petsc4py import PETSc

# ---- your existing mesh, bc_map, D_mol, etc. -----------------
# (assume they are already defined)

# Build a list of the FiPy CellVariables that you want to integrate
c_vars = [getattr(c, s) for s in species_list_partial]   # length = Nspecies

# --------------------------------------------------------------
# 2️⃣  Create a PETSc Vec that will hold the concatenated solution
# --------------------------------------------------------------
ndof = sum(v.nCells for v in c_vars)          # total unknowns = Nspecies * nCells
vec = PETSc.Vec().createSeq(ndof)

def pack_solution():
    """Copy FiPy variables → PETSc Vec (row‑wise)."""
    offset = 0
    for v in c_vars:
        n = v.nCells
        vec[offset:offset+n] = v.value.ravel()
        offset += n

def unpack_solution():
    """Copy PETSc Vec → FiPy variables (after a TS step)."""
    offset = 0
    for v in c_vars:
        n = v.nCells
        v.value = vec[offset:offset+n].reshape(v.shape)
        offset += n

# initialise the PETSc vector with the current FiPy state
pack_solution()

# --------------------------------------------------------------
# 3️⃣  Define the RHS function for PETSc TS (dC/dt = F(C))
# --------------------------------------------------------------
def rhs(ts, t, X, F):
    """X is a PETSc Vec (current state), F will receive dC/dt."""
    # 1) copy X into FiPy variables
    X.copy(vec)          # ensure X is the global vec
    unpack_solution()   # now FiPy variables contain the state at time t

    # 2) evaluate reaction rates (your diagenetic_reactions & equilibrium)
    f_res, RATES = diagenetic_reactions(mp, c, k, f=data_container())
    _, RATES_eq = equilibrium_reactions(mp, c, k, None, {}, mp.dt_min)

    # 3) update all coefficient CellVariables (lhs, rhs, cross, etc.)
    for s_obj in species_struct:
        name = s_obj["name"]
        tup = getattr(f_res, name)
        s_obj["lhs"].setValue(getattr(tup[0], "value", tup[0]))
        s_obj["rhs"].setValue(getattr(tup[1], "value", tup[1]))
        if len(tup) > 3:
            for src, coeff in tup[3]:
                s_obj["cross"][src].setValue(getattr(coeff, "value", coeff))

    # 4) Build the residual of the *steady* (no transient) FiPy equation:
    #    0 = -TransientTerm + Conv + Diff + Source
    #    →   dC/dt =  Conv + Diff + Source - (lhs* C + rhs)
    #    The left‑hand side of each FiPy equation is exactly the matrix
    #    that PETSc already built when you called `eq.sweep(...)`.
    #    Here we ask FiPy to give us the RHS vector for the current state.
    #    (We reuse the same matrix that PETSc built in the first step.)
    #    NOTE: the matrix does NOT change because we only update the
    #    diagonal coefficients (lhs_vars, rhs_vars, cross terms) which
    #    are stored as separate CellVariables.

    # Build a *temporary* FiPy residual (vector) – we reuse the same
    # coupled equation object you already built.
    residual = coupled_eq.residual()
    # residual is a NumPy array of shape (ndof,); copy into PETSc Vec F
    F.setArray(residual)

# --------------------------------------------------------------
# 4️⃣  Create the TS object (BDF2) and tell PETSc to reuse the matrix
# --------------------------------------------------------------
ts = PETSc.TS().create()
ts.setProblemType(PETSc.TS.ProblemType.NONLINEAR)   # we supply a residual
ts.setRHSFunction(rhs, F=vec)                     # F is the work vector
ts.setType(PETSc.TS.Type.BE)                     # backward‑Euler for first step
ts.setExactFinalTime(PETSc.TS.ExactFinalTime.INTERPOLATE)

# Use BDF2 after the first step
ts.setTolerances(rtol=mp.tolerance, atol=1e-12)
ts.setMaxSteps(mp.max_steps)
ts.setTimeStep(mp.dt_min)                        # initial guess
ts.setMaxStepSize(mp.dt_max)

# Choose a linear solver for the Jacobian (the same matrix you built)
# – we ask PETSc to compute the Jacobian *automatically* by finite differencing
# – but you can supply your own Jacobian via `setRHSJacobian` if you want.
ksp = PETSc.KSP().create()
ksp.setType('gmres')
ksp.getPC().setType('hypre')                     # or 'ilu' for 1‑D
ts.setLinearSolver(ksp)

# --------------------------------------------------------------
# 5️⃣  Run the time loop
# --------------------------------------------------------------
t = 0.0
while t < mp.t_end:
    ts.step(t + mp.dt_max)          # PETSc chooses its own sub‑step size
    t = ts.getTime()
    # Pull the new solution back into FiPy for diagnostics / output
    ts.getSolution(vec)
    unpack_solution()

    # ---- your normal reporting / saving code ----
    if step % mp.report_step == 0:
        print(f"t = {t:.2e}  dt (chosen by PETSc) = {ts.getTimeStep():.2e}")
        # e.g. save_data_async(...)

print("Finished – PETSc TS used BDF2 (after the first step).")
#+end_src

*Key points of the wrapper*

- The *first step* is backward‑Euler (=BE=) – PETSc needs a first‑order start.
- After that PETSc automatically switches to *BDF2* (second‑order, A‑stable) because we never change the =ts= type.
- =rhs= builds the /same/ residual that FiPy would use for a linear sweep, so you keep all your chemistry logic unchanged.
- The *linear system* inside each TS sub‑step is solved by the same =ksp= you already tuned (GMRES + hypre).  
  For 1 D you can even change it to =pc_type='lu'= – it will be super cheap.

sol = solve_ivp(
    f,
    (0, mp.t_end),
    y0,
    method='BDF',                # variable‑order, A‑stable
    rtol=mp.tolerance,
    atol=1e-12,
    max_step=mp.dt_max,         # optional upper bound on step size
    vectorized=False,
)

# sol.t and sol.y contain the full time history; you can loop over them
# and feed back into FiPy for post‑processing if you need the full field.
#+end_src

/Pros/: no extra PETSc install, works on Windows, single‑core.  
/Cons/: each RHS evaluation rebuilds the FiPy matrix (still cheap for ≤ 1 000 cells) and the Jacobian is approximated by finite differences (SciPy does that internally).

** 3️⃣  Practical “speed‑up” checklist for your 1‑D, super‑stiff case  

| # | Action | Expected gain |
|---|--------|---------------|
| 1 | *Switch to a direct LU* (=ksp_type='preonly', pc_type='lu'=) – matrix size ≈ Nspecies × Ncells ≤ 5 000 → solve in < 1 ms. | Eliminates iterative‑solver overhead. |
| 2 | *Use PETSc TS with BDF2* (or SciPy BDF). | Allows /orders of magnitude/ larger Δt while keeping the same tolerance. |
| 3 | *Apply your equilibrium reactions /before/ the transport solve* (operator splitting). | Removes the stiffest algebraic constraints from the Jacobian, improving conditioning. |
| 4 | *Scale all variables* to O(1) (e.g. concentrations in µM, time in years). | Improves the linear‑solver convergence and reduces round‑off. |
| 5 | *Turn on adaptive time stepping* (=growth_factor ≈ 1.5–2.0=, =cut_factor ≈ 0.5=). | The solver automatically backs off when a step fails, so you never waste time with overly tiny steps. |
| 6 | *Cache coefficient objects* (you already do this). | Removes the Python‑level overhead of =getattr= in the inner loop. |
| 7 | *Parallelise the /reaction/ evaluation* (if you have many species). | =diagenetic_reactions= is pure Python – you can =multiprocessing.Pool.map= the per‑cell chemistry; the linear solve stays serial because the matrix is tiny. |
| 8 | *Profile* (=%timeit= or =cProfile=) to see where the wall‑time is spent after the above changes. | Guarantees you are not optimizing the wrong part. |
